produto

A/B Test

Teste que compara duas versões de uma mesma experiência para medir qual funciona melhor.

Ele é usado para decidir com dado real em vez de opinião quando duas hipóteses parecem plausíveis.

Exemplo: Ex.: testar dois textos de botão de cadastro e ver qual gera mais conclusão.
produto

Agile

Forma de organizar trabalho em ciclos curtos, com entrega frequente e feedback constante.

No dia a dia aparece em sprint, refinamento, retrospectiva e ajuste de rota conforme aprendizado do time.

Exemplo: Ex.: dividir uma funcionalidade grande em entregas menores para validar valor antes de investir meses.
fundamentos

Algoritmo

É uma receita finita e não ambígua que transforma entrada em saída. Em entrevistas, pedem algoritmos não por sadismo, mas para ver se você raciocina sobre custo e casos extremos.

Analisar complexidade (Big O) responde como tempo e memória crescem quando o input dobra. Estruturas de dados (filas, heaps, árvores) escolhidas certas tornam operações baratas. No trabalho diário, algoritmo aparece em caches, agendadores, deduplicação e roteamento, não só em exercícios de livro.

Exemplo: Encontrar duplicatas em milhões de registros: hash set O(n) bate força bruta O(n²). Escolher errado significa job que rodava em minutos passar a rodar em horas.
back-end

API

É o contrato público pelo qual um sistema expõe dados ou ações para outro programa, sem abrir o código interno. Sem APIs, cada app precisaria duplicar bancos inteiros ou integrações frágeis via telas automatizadas.

API (Application Programming Interface) descreve URLs, formatos de dados e regras de autenticação que outro time ou outro serviço deve seguir. Ela pode ser REST, GraphQL, fila de mensagens ou gRPC; o ponto comum é padronizar a conversa entre sistemas. Boas APIs versionam mudanças, documentam erros e pensam em segurança desde o primeiro dia, porque qualquer cliente externo vai confiar no comportamento documentado.

Exemplo: No delivery, ao tocar em "pagar com cartão", o app não acessa o mainframe do banco: ele chama a API de pagamentos, recebe um status e mostra o resultado. Se a API mudar sem aviso, vários apps quebram ao mesmo tempo. Por isso contrato e testes importam tanto.
cloud

API Gateway

Camada que centraliza entrada de APIs, autenticação, roteamento e políticas comuns.

Ela evita repetir controle de acesso, rate limit e observabilidade em cada serviço isolado.

Exemplo: Ex.: várias APIs internas ficam atrás de um gateway que valida token antes de repassar a chamada.
seguranca

Autenticação

Processo de provar quem você é antes de usar um sistema.

Senha, MFA, biometria e login social são meios de autenticação com níveis diferentes de risco.

Exemplo: Ex.: usuário informa senha e código do autenticador antes de entrar no painel.
seguranca

Autorização

Regra que define o que cada pessoa ou serviço pode fazer depois de autenticado.

Autenticar não basta; o sistema ainda precisa limitar ação, escopo e acesso conforme o papel.

Exemplo: Ex.: analista vê pedido, mas só gerente pode aprovar reembolso.
back-end

Back-end

É a camada que roda fora do navegador do usuário: servidores, regras de negócio, integrações e persistência. O usuário não "vê" o back-end, mas sente quando ele está lento, inconsistente ou inseguro.

Back-end recebe requisições (HTTP, filas, jobs agendados), valida permissões, fala com bancos e serviços externos e devolve respostas confiáveis. Ele também é onde moram preocupações como transações, concorrência, idempotência e auditoria. Times grandes separam camadas (API, domínio, infraestrutura), mas no início o importante é entender o fluxo ponta a ponta: pedido entra, dado é validado, efeito colateral é controlado, resposta sai.

Exemplo: Quando você redefine senha, o front só coleta o formulário; o back-end gera token seguro, envia e-mail, invalida sessões antigas e registra o evento. Se algo falhar no meio, o sistema precisa falhar de forma previsível, não corromper dados.
back-end

Banco de dados

É o sistema onde dados duráveis ficam organizados, indexados e protegidos por regras (tipos, constraints, transações). Sem banco bem modelado, o aplicativo vira planilha compartilhada com concorrência e perda de informação.

Bancos relacionais (PostgreSQL, MySQL) usam tabelas e SQL; NoSQL (MongoDB, Redis) favorecem documentos, chave-valor ou grafos conforme o caso. A escolha impacta consistência, velocidade de leitura e complexidade de consultas. Migrações de esquema, backups e replicação fazem parte do trabalho real, não só "criar tabela" uma vez.

Exemplo: Em e-commerce, estoque e pedidos precisam ser transacionais: dois clientes não podem comprar o último item ao mesmo tempo sem regra no banco. O back-end escreve em transação; se falhar, nada fica pela metade.
geral

Biblioteca (lib)

É código reutilizável que você importa para uma tarefa pontual: datas, validação, gráficos, HTTP client. Você decide quando chamar; a biblioteca não manda na arquitetura inteira.

Bibliotecas bem mantidas têm semver, changelog e testes; ruins viram dívida técnica silenciosa. Em JavaScript, npm distribui pacotes. Sempre verifique licença, tamanho no bundle e última atualização. Combinar dezenas de libs pequenas sem critério explode a superfície de vulnerabilidades e o tempo de build.

Exemplo: Para formatar moeda em real e timezone de Brasília, uma lib como date-fns ou Intl API evita reimplementar calendário. Você importa a função, usa no componente e segue, sem precisar de framework novo.
dados

Big Data

Conjunto de técnicas e arquitetura para lidar com volume, velocidade ou variedade muito altos.

Big Data importa quando ferramenta simples deixa de dar conta com segurança, tempo ou custo aceitável.

Exemplo: Ex.: processar bilhões de eventos de navegação por dia para análise e recomendação.
geral

Branch (Git)

Linha paralela de trabalho em um repositório para mudar algo sem tocar direto na base principal.

Branch permite experimentar, revisar e isolar uma entrega antes de mesclar no fluxo principal.

Exemplo: Ex.: criar branch da nova feature para trabalhar sem quebrar a versão estável.
qa

Bug

Erro de comportamento entre o que o sistema faz e o que deveria fazer.

Bug pode nascer de código, requisito ambíguo, integração ruim ou dado inesperado.

Exemplo: Ex.: desconto é aplicado duas vezes quando a página recarrega.
infra

Cache

Cópia temporária de dado usado com frequência para reduzir tempo e custo de acesso.

Cache acelera leitura, mas também cria desafio de invalidação e consistência entre camadas.

Exemplo: Ex.: guardar lista de produtos populares em cache para não consultar o banco a cada visita.
cloud

CDN

Rede distribuída que entrega arquivos mais perto do usuário final.

CDN reduz latência, alivia servidor principal e melhora disponibilidade para conteúdo estático.

Exemplo: Ex.: imagens do site são servidas por uma CDN em vez de sair sempre do mesmo servidor.
infra

CI/CD

CI integra código novo continuamente e roda verificações automáticas; CD estende isso até entrega ou deploy, quando os gates de qualidade passam. Juntos, reduzem surpresas na véspera de release.

Pipeline típico: lint, testes unitários, build, análise de segurança (SAST), publicação de artefato e promoção entre ambientes. CD pode ser "delivery" (humano aprova) ou "deployment" totalmente automático. Sem CI, bugs regressivos voltam sem ser notados; sem CD, correções urgentes demoram horas por burocracia manual.

Exemplo: Cada pull request roda 200 testes em minutos; merge na main gera imagem Docker versionada e atualiza homologação. Produção só recebe tag aprovada pelo time, seja com botão ou política automática.
infra

CLI

Interface de linha de comando usada por texto em vez de interface gráfica.

CLI é comum em servidor, automação, cloud e ferramentas que precisam ser scriptáveis.

Exemplo: Ex.: usar CLI da AWS para criar recursos em lote sem clicar no console.
cloud

Cloud (nuvem)

É consumir computação, armazenamento e rede como serviço pago pelo uso, em vez de comprar hardware próprio. AWS, GCP e Azure são os grandes provedores; há também opções menores e especializadas.

Na cloud você provisiona máquinas em minutos, anexa discos, configura VPC e integra serviços gerenciados (banco, fila, CDN). O modelo shifta custo de CAPEX para OPEX e exige disciplina financeira: recursos esquecidos geram conta alta. Boas equipes usam infraestrutura como código (Terraform, Pulumi) para não clicar manualmente em console.

Exemplo: Black Friday: auto scaling adiciona instâncias quando CPU sobe e reduz depois do pico. Em datacenter próprio, você teria capacidade ociosa o ano inteiro ou risco de queda no pico.
cloud

Cloud Computing

Modelo de computação em que processamento, rede e armazenamento são consumidos como serviço.

Ele amplia elasticidade e terceiriza parte da operação física do datacenter.

Exemplo: Ex.: aumentar capacidade de processamento em campanha sem comprar hardware novo.
cloud

Cluster

Grupo de máquinas ou instâncias trabalhando juntas como um conjunto coordenado.

Cluster aparece em banco, containers e processamento distribuído para ganhar escala e resiliência.

Exemplo: Ex.: um cluster de Kubernetes distribui pods entre vários nós.
geral

Commit

Registro versionado de um conjunto de mudanças com mensagem descritiva.

Commit bom explica intenção e facilita review, bisect e entendimento histórico do projeto.

Exemplo: Ex.: separar correção de bug de refatoração em commits diferentes melhora rastreabilidade.
cloud

Container

Empacotamento leve de aplicação com dependências e configuração de execução.

Container ajuda a rodar o mesmo software em ambientes diferentes com menos surpresa.

Exemplo: Ex.: app sobe em container igual no notebook, na pipeline e em produção.
geral

Controle de versão (Git)

É o sistema que registra cada mudança no código: quem alterou, quando e por quê. Git é o padrão de mercado; hospedar no GitHub/GitLab é só camada colaborativa em cima.

Com Git você cria branches para features, revisa diffs antes de integrar e volta no tempo quando necessário. Fluxos como trunk-based ou Gitflow organizam como merges acontecem. Integração com CI roda testes a cada push. Sem versionamento, isso simplesmente não existe de forma confiável.

Exemplo: Você quebrou produção sexta à noite: o histórico mostre o commit culpado, você abre revert ou hotfix branch, e o time discute em PR o que aprender. Sem Git, você caça cópia "final_v2_really.zip".
front-end

Cookie

Pequeno dado salvo no navegador para sessão, preferência ou rastreamento.

Cookie precisa ser tratado com cuidado porque pode carregar informação sensível ou sujeita a consentimento.

Exemplo: Ex.: login persiste sessão por cookie HttpOnly definido pelo servidor.
back-end

CORS

Regra do navegador que controla quando uma origem pode acessar recurso de outra.

CORS existe para limitar acesso cruzado e precisa ser configurado de forma explícita na API.

Exemplo: Ex.: front em um domínio faz chamada para API em outro e recebe bloqueio por política de origem.
back-end

CRUD

Conjunto básico de operações de criar, ler, atualizar e apagar dados.

Muita aplicação começa com CRUD, mas produto real logo adiciona regra, permissão e auditoria em cima.

Exemplo: Ex.: painel administrativo cadastra, lista, edita e remove clientes.
front-end

CSS

É a folha de estilo que controla aparência e, em parte, layout responsivo: cores, tipografia, grid, flexbox, animações. CSS "simples" esconde anos de pegadinhas entre navegadores e especificidade.

Design systems modernos usam tokens, variáveis e componentes para manter consistência. Performance importa: seletores pesados, animações que disparam layout thrashing e imagens sem tamanho definido prejudicem Core Web Vitals. Pré-processadores (Sass) e frameworks (Tailwind) são opcionais; o fundamento é o cascade e o box model.

Exemplo: Mesmo conteúdo HTML pode virar layout mobile-first com media queries: menu vira ícone, colunas viram pilha, fonte aumenta para leitura confortável. Isso é trabalho de CSS, não só "deixar bonito no Figma".
dados

Dashboard

Tela que resume métricas e sinais importantes para tomada de decisão.

Dashboard bom mostra contexto, tendência e ação; dashboard ruim vira painel bonito sem prioridade.

Exemplo: Ex.: produto acompanha conversão, retenção e erro em um único painel diário.
dados

Data Lake

Repositório para armazenar dados brutos em grande volume e formatos variados.

Ele é útil quando você ainda não sabe todas as perguntas futuras, mas precisa governança para não virar bagunça.

Exemplo: Ex.: guardar logs, eventos e arquivos de várias fontes para análise posterior.
dados

Data Visualization

Transformação de dados em gráficos ou visuais que ajudam a entender padrão e exceção.

Boa visualização reduz ruído e ajuda a pessoa certa a agir mais rápido.

Exemplo: Ex.: trocar tabela gigante por gráfico de tendência semanal para evidenciar queda de conversão.
dados

Data Warehouse

Base organizada para consulta analítica, com modelagem pensada para relatório e BI.

Warehouse privilegia leitura confiável e histórica para decisão de negócio.

Exemplo: Ex.: financeiro e produto consultam o mesmo repositório consolidado de vendas mensais.
geral

Debug (depuração)

É o processo sistemático de reproduzir falha, isolar causa e provar a correção. Boa depuração mistura leitura de stack trace, logs, breakpoints e hipóteses testáveis.

Debug não é "tentar coisas até funcionar" indefinidamente. É reduzir o espaço de busca. Você bissecta commits, minimiza caso de teste e adiciona instrumentação temporária. Em sistemas distribuídos, correlacionar request IDs entre serviços é parte do ofício. Documentar a causa raiz evita que o bug volte disfarçado.

Exemplo: Produção retorna 500 só para alguns usuários: você compara payload, descobre string vazia onde número era esperado, adiciona validação no back-end e teste de regressão. Sem debug disciplinado, alguém coloca if espalhado que mascara o sintoma.
infra

Deploy

É o ato de levar uma versão testada do software para um ambiente onde usuários ou outros sistemas acessam. Deploy manual existe, mas em empresas maduras ele é repetível, rastreável e reversível.

Deploy envolve empacotar artefatos (binários, assets estáticos, migrações de banco), aplicar configurações por ambiente (dev, homologação, produção) e validar saúde após publicar. Ferramentas modernas usam pipelines: build, testes, análise de segurança, liberação gradual (canary) e rollback automático se métricas piorarem. Sem disciplina de deploy, cada correção vira medo e cada sexta-feira vira apagão.

Exemplo: Você corrigiu um bug no cálculo de frete: após merge na branch principal, o pipeline publica nova versão no servidor, roda smoke tests e só então o tráfego passa a usar o build novo. Se o erro voltar, você reverte para o artefato anterior em minutos.
infra

DevOps

É cultura e prática de encurtar o caminho entre ideia e produção, com feedback rápido e responsabilidade compartilhada. Não é um cargo único em todos os lugares; às vezes é time de plataforma, às vezes há SRE separado.

DevOps incentiva automação de build, testes, deploy, observabilidade (logs, métricas, traces) e postmortem sem culpar indivíduo. Ferramentas são meio: Docker, Kubernetes, GitHub Actions, Prometheus. O fim é reduzir lead time e aumentar confiabilidade percebida pelo usuário.

Exemplo: Antes, deploy era evento mensal com checklist de medo; depois de DevOps maduro, deploys pequenos e frequentes reduzem risco porque mudanças são isoladas e monitoradas.
cloud

DNS

Sistema que traduz nome amigável em endereço de rede.

Sem DNS, pessoas teriam de decorar IP; com DNS mal configurado, site some mesmo com servidor vivo.

Exemplo: Ex.: dominio.com aponta para o balanceador correto por registro DNS.
cloud

Docker

Ferramenta popular para construir e rodar containers.

Docker empacota aplicação e dependências em imagem reproduzível para vários ambientes.

Exemplo: Ex.: pipeline gera imagem Docker do app e publica em um registry antes do deploy.
back-end

Endpoint

Ponto específico de acesso de uma API, normalmente identificado por rota e método.

Cada endpoint representa uma operação exposta e deve ser documentado com entrada, saída e erros.

Exemplo: Ex.: POST /pedidos cria um novo pedido no sistema.
dados

ETL

Processo de extrair, transformar e carregar dados entre sistemas.

ETL aparece quando dado vem sujo ou espalhado e precisa virar fonte confiável de análise.

Exemplo: Ex.: juntar vendas de loja, site e marketplace em uma tabela única para BI.
geral

Feature Branch

Branch criada para desenvolver uma funcionalidade isolada da base principal.

Ela facilita revisão, teste e rollback sem misturar trabalho inacabado com código estável.

Exemplo: Ex.: checkout novo vive em feature branch até ficar pronto para PR.
produto

Feature Flag

Chave que liga ou desliga uma funcionalidade sem redeploy completo.

Ela ajuda rollout gradual, teste controlado e reversão rápida de comportamento.

Exemplo: Ex.: liberar novo checkout só para 10 por cento dos usuários antes da abertura total.
seguranca

Firewall

Camada que filtra tráfego de rede conforme regra definida.

Firewall reduz superfície de ataque ao bloquear portas, origens ou protocolos indevidos.

Exemplo: Ex.: banco aceita conexão só da sub-rede da aplicação, não da internet inteira.
geral

Framework

É um esqueleto opinativo que define como organizar pastas, rotas, injeção de dependências e ciclo de vida da aplicação. Você preenche os vazios; o framework chama seu código nos momentos certos.

Frameworks aceleram porque já resolvem problemas comuns: roteamento, autenticação, ORM, build e testes. O custo é acoplar decisões ao ecossistema escolhido e acompanhar atualizações. Biblioteca, em contraste, você chama quando precisa; framework costuma inverter o controle. Escolher errado no início não é tragédia, mas trocar depois dói. Por isso times documentam critérios de escolha.

Exemplo: Em vez de configurar servidor HTTP do zero, você usa Express ou Fastify em Node, ou Django em Python, e foca nas rotas do seu domínio. O framework já traz middlewares, parsing de JSON e convenções de erro.
front-end

Front-end

É tudo o que roda no dispositivo da pessoa: layout, estados de tela, formulários, animações e acessibilidade. Bom front-end não é só estética: é engenharia de interface que lida com latência, erros de rede e diferentes tamanhos de tela.

Front-end tradicionalmente combina HTML semântico, CSS e JavaScript, hoje frequentemente com frameworks que gerenciam estado e roteamento. O trabalho inclui performance (menos JavaScript desnecessário, imagens adequadas), compatibilidade entre navegadores e testes de usabilidade. Em produtos reais, front-end conversa com design e produto para traduzir requisitos em componentes reutilizáveis.

Exemplo: No banco pelo celular, o extrato que você vê é front-end; o saldo veio de uma API, mas quem decide como mostrar loading, retry e mensagem de erro é a camada de interface. Uma tela bonita que trava com 500 linhas na lista não passa em revisão séria.
geral

Git

Ferramenta de controle de versão usada para histórico, branches, merges e colaboração.

Git permite experimentar com segurança e saber exatamente quando e por que algo mudou.

Exemplo: Ex.: bug em produção é rastreado até o commit que alterou a regra de desconto.
back-end

GraphQL

Forma de API em que cliente pede exatamente os campos que precisa.

GraphQL reduz excesso de dados em algumas integrações, mas exige atenção extra com custo de consulta e cache.

Exemplo: Ex.: tela de perfil busca só nome e avatar sem baixar objeto inteiro de usuário.
seguranca

Hash

Saída curta e determinística gerada a partir de um dado de entrada.

Hash é usado em integridade, senha, cache e identificação; não serve como criptografia reversível.

Exemplo: Ex.: sistema guarda hash da senha em vez da senha em texto puro.
qa

Help Desk

Ponto de atendimento técnico para incidentes, dúvidas e problemas operacionais.

Help desk é porta de entrada comum em tecnologia porque expõe sistema, usuário e processo ao mesmo tempo.

Exemplo: Ex.: colaborador abre chamado porque perdeu acesso ao e-mail e o time de suporte investiga.
front-end

HTML

É a camada de marcação que dá estrutura e significado ao conteúdo: títulos, listas, formulários, landmarks para leitores de tela. HTML não é linguagem de lógica; combina com CSS e JS.

HTML5 trouxe tags semânticas (header, nav, main, article) que melhoram SEO e acessibilidade. Atributos como alt em imagens e labels em inputs não são detalhe cosmético: são requisitos legais e de inclusão em muitos mercados. Validar HTML ajuda a evitar comportamento estranho entre navegadores.

back-end

HTTP/HTTPS

Protocolo usado na web para troca de requisição e resposta, com ou sem camada segura.

HTTPS adiciona TLS para proteger dados em trânsito e evitar interceptação simples.

Exemplo: Ex.: navegador envia GET para buscar página e recebe HTML como resposta.
cloud

IaC (Infrastructure as Code)

Definição de infraestrutura em arquivo versionado, em vez de clique manual.

IaC melhora repetibilidade, revisão e recuperação de ambiente, além de reduzir configuração invisível.

Exemplo: Ex.: Terraform cria VPC, banco e balanceador a partir de código revisado em PR.
geral

IDE

Ambiente integrado de desenvolvimento com editor, debug, terminal e navegação de código.

IDE aumenta produtividade quando usada para entender projeto, testar e refatorar com segurança.

Exemplo: Ex.: VS Code ou IntelliJ ajudam a renomear função em vários arquivos sem erro manual.
back-end

Idempotência

Propriedade de repetir a mesma operação sem mudar o resultado além da primeira vez.

Idempotência evita efeito colateral duplicado em reprocessamento, retry ou timeout de rede.

Exemplo: Ex.: reenvio do mesmo pedido de pagamento não pode cobrar duas vezes o cartão.
dados

Índice

Estrutura auxiliar que acelera busca em banco de dados.

Índice melhora leitura, mas custa espaço e escrita; escolher demais ou de menos dá problema.

Exemplo: Ex.: indexar e-mail acelera login por usuário sem varrer tabela inteira.
infra

Integração Contínua

Prática de integrar mudanças pequenas com validação automatizada frequente.

O objetivo é descobrir erro cedo, antes de ele virar surpresa grande na release.

Exemplo: Ex.: cada push roda testes e impede merge de código que quebrou a build.
cloud

IP

Endereço numérico usado para identificar dispositivo ou serviço na rede.

IP pode ser público ou privado e influencia roteamento, firewall e acesso entre máquinas.

Exemplo: Ex.: servidor interno usa IP privado e só o balanceador possui IP público.
front-end

JavaScript

É a linguagem que roda nos navegadores para eventos, estado e comunicação com APIs; com Node.js, também roda em servidores e ferramentas de build. Ecossistema enorme exige curadoria do que você instala.

JS moderno (ES modules, async/await, fetch) simplifica código assíncrono, mas exige entender promises e fila de eventos. Tipagem opcional com TypeScript reduz bugs em projetos médios e grandes. Bundlers (Vite, Webpack) transformam e otimizam código para produção.

Exemplo: Ao digitar em uma busca, JS debounce evita disparar requisição a cada tecla; ao receber JSON da API, JS atualiza o DOM ou framework reativo re-renderiza só o necessário.
dados

JOIN

Operação SQL que combina linhas de tabelas diferentes por uma relação comum.

JOIN é poderoso, mas join mal feito duplica dado, distorce métrica e piora performance.

Exemplo: Ex.: juntar pedidos e clientes para saber ticket médio por cidade.
back-end

JSON

Formato textual simples muito usado para trocar dados entre sistemas.

JSON aparece em API, config, fila e armazenamento leve por ser legível e amplamente suportado.

Exemplo: Ex.: front envia um objeto JSON com nome, e-mail e telefone para criar cadastro.
seguranca

JWT

Token assinado que carrega claims e pode representar autenticação ou autorização temporária.

JWT facilita integrações, mas precisa expiração curta, assinatura válida e cuidado com dado sensível.

Exemplo: Ex.: API recebe JWT no header para identificar usuário autenticado.
cloud

Kubernetes

Plataforma de orquestração de containers para escalar, distribuir e recuperar aplicações.

Kubernetes resolve operação complexa em escala, mas cobra curva de aprendizado e disciplina alta.

Exemplo: Ex.: cluster redistribui pods quando um nó cai.
infra

Latência

Tempo que um pedido leva para sair, viajar e voltar com resposta.

Latência afeta experiência percebida e pode vir de rede, banco, código ou dependência externa.

Exemplo: Ex.: busca demora 800 ms porque consulta bate API externa lenta em cascata.
cloud

Load Balancer

Camada que distribui tráfego entre várias instâncias de serviço.

Balanceador melhora escala e disponibilidade, além de permitir health check e failover.

Exemplo: Ex.: tráfego do site é dividido entre três servidores de aplicação ativos.
infra

Log

Registro textual ou estruturado de eventos relevantes do sistema.

Log bom ajuda debug, auditoria e investigação; log ruim gera barulho sem contexto.

Exemplo: Ex.: request id no log permite seguir a mesma chamada por vários serviços.
dados

Machine Learning

Uso de modelos que aprendem padrão a partir de dados para prever ou classificar algo.

Machine learning depende muito mais de dado, pergunta e validação do que de algoritmo glamouroso.

Exemplo: Ex.: classificar e-mail como spam com base em histórico rotulado.
geral

Merge

Ato de combinar mudanças de uma branch em outra.

Merge exige entender conflito e intenção, não só clicar em aceitar tudo.

Exemplo: Ex.: branch de feature entra na main depois de review e testes.
back-end

Microsserviços

Arquitetura em que o sistema é dividido em serviços menores e independentes.

Microsserviços ajudam autonomia em escala, mas aumentam integração, observabilidade e custo operacional.

Exemplo: Ex.: serviço de pagamento evolui separado do serviço de catálogo.
back-end

Migration (banco de dados)

Arquivo versionado que altera esquema ou dado de banco de forma rastreável.

Migration evita mudança manual esquecida entre ambientes e ajuda rollback planejado.

Exemplo: Ex.: adicionar coluna status na tabela de pedidos por migration revisada em PR.
back-end

Monolito

Aplicação concentrada em um único deploy ou base principal de código.

Monolito não é sinônimo de ruim; muitas empresas saudáveis preferem monolito bem cuidado a microsserviço prematuro.

Exemplo: Ex.: back-end inteiro publica junto em um único artefato e banco principal.
fundamentos

MVC

Padrão que separa modelo, visão e controlador em papéis diferentes.

MVC ajuda organização em projetos tradicionais, embora frameworks modernos adaptem a ideia de formas diferentes.

Exemplo: Ex.: controller recebe requisição, model busca dado e view monta resposta.
produto

MVP

Versão mínima de um produto que já permite aprender com usuário real.

MVP não é produto malfeito; é recorte consciente para testar hipótese com o menor custo útil.

Exemplo: Ex.: lançar agenda simples antes de construir suíte inteira de gestão clínica.
back-end

NoSQL

Família de bancos que não segue o modelo relacional tradicional como regra central.

NoSQL pode ser ótimo para documento, chave-valor, cache ou grafo, mas não substitui modelagem.

Exemplo: Ex.: usar Redis para sessão e MongoDB para documento flexível de catálogo.
seguranca

OAuth

Protocolo de autorização usado para conceder acesso controlado entre aplicações.

OAuth é comum em login com terceiros e integrações em que a senha do usuário não deve ser compartilhada.

Exemplo: Ex.: aplicativo conecta conta Google sem pedir a senha do Gmail.
infra

Observabilidade

Capacidade de entender o estado interno do sistema por sinais externos como log, métrica e trace.

Observabilidade boa reduz tempo de diagnóstico quando o sistema falha em produção.

Exemplo: Ex.: trace mostra que lentidão veio do serviço de recomendação e não do banco.
fundamentos

OOP (Orientação a Objetos)

Estilo de modelagem baseado em objetos com estado e comportamento.

OOP ajuda em certos domínios, mas vira problema quando usada por ritual sem clareza do problema.

Exemplo: Ex.: classe Pedido concentra regra de fechamento e cálculo de desconto.
geral

Open source

É software cujo código-fonte é público sob licença que permite estudar, modificar e redistribuir, dentro de regras legais claras. Não confundir com "grátis": muitas empresas lucram com suporte e serviços em cima de open source.

Projetos como Linux, Kubernetes e React movem a indústria porque milhares de olhos acham bugs e porque empresas compartilham custo de manutenção. Contribuir com documentação ou testes já conta como participação legítima. Entender licenças (MIT, Apache, GPL) evita surpresas quando você incorpora código em produto comercial.

Exemplo: Sua empresa usa PostgreSQL sem pagar licença, mas paga consultoria e suporte. O código é aberto; a operação 24x7 com SLA é que tem preço.
back-end

ORM

Ferramenta que traduz objetos ou estruturas da linguagem para operação no banco.

ORM acelera CRUD comum, mas não elimina a necessidade de entender SQL e custo de consulta.

Exemplo: Ex.: framework gera query para buscar usuário por e-mail sem escrever SQL manual em todo lugar.
seguranca

Par de chaves

Conjunto de chave pública e chave privada usado em criptografia assimétrica.

Esse modelo permite autenticar ou criptografar sem compartilhar o mesmo segredo em ambos os lados.

Exemplo: Ex.: SSH usa chave privada local e chave pública no servidor para liberar acesso.
back-end

Payload

Parte útil dos dados transportados em uma requisição, resposta ou mensagem.

Payload precisa ser validado e documentado para evitar quebra silenciosa entre sistemas.

Exemplo: Ex.: webhook envia payload JSON com id do pedido, status e horário da mudança.
infra

Pipeline

Sequência automatizada de etapas para validar, empacotar ou publicar software e dados.

Pipeline reduz erro manual e garante que cada mudança passe pelo mesmo fluxo mínimo.

Exemplo: Ex.: pipeline roda testes, gera imagem e publica deploy após merge.
cloud

Pod (Kubernetes)

Menor unidade de execução no Kubernetes, podendo conter um ou mais containers relacionados.

Pod encapsula processo, rede e volume em torno da aplicação que o cluster vai agendar.

Exemplo: Ex.: API sobe em pods replicados para atender mais tráfego.
fundamentos

Polimorfismo

Capacidade de tratar implementações diferentes sob a mesma interface ou contrato.

Polimorfismo ajuda extensão e teste quando o sistema precisa variar comportamento sem copiar tudo.

Exemplo: Ex.: meios de pagamento diferentes expõem o mesmo método processar.
geral

Pull Request

Pedido formal para revisar e integrar mudanças de uma branch em outra.

PR é espaço de revisão técnica, contexto e discussão antes de mergear código.

Exemplo: Ex.: dev abre PR explicando escopo, risco e prints da funcionalidade nova.
qa

QA

Prática e área focadas em qualidade, prevenção de regressão e confiança no software.

QA bom combina caso de teste, automação, exploração e análise de risco.

Exemplo: Ex.: antes da release, QA valida checkout, login e pagamento em cenários críticos.
dados

Query

Instrução para buscar, filtrar ou transformar dados em um sistema de armazenamento.

Query pode ser SQL, GraphQL ou linguagem própria; o importante é custo e precisão do resultado.

Exemplo: Ex.: query busca usuários ativos nos últimos 30 dias por plano.
back-end

Queue (Fila de mensagens)

Mecanismo para processar trabalho de forma assíncrona e desacoplada.

Fila ajuda a absorver pico, retentar tarefa e tirar peso do fluxo síncrono principal.

Exemplo: Ex.: após compra, sistema enfileira envio de e-mail e geração de nota fiscal.
infra

RAID

Combinação de discos para melhorar redundância, desempenho ou ambos.

RAID protege contra falha de disco individual, mas não substitui backup nem estratégia de recuperação.

Exemplo: Ex.: servidor mantém espelhamento entre discos para continuar operando se um falhar.
seguranca

Rate Limit

Limite de requisições aceitas em certo período para um cliente ou origem.

Rate limit ajuda a controlar abuso, proteger serviço e evitar explosão de custo.

Exemplo: Ex.: API pública permite até 100 chamadas por minuto por chave.
fundamentos

Recursão

Técnica em que uma função chama a si mesma até atingir condição de parada.

Recursão é elegante em árvore e divisão de problema, mas precisa de base clara para não quebrar.

Exemplo: Ex.: percorrer pastas dentro de pastas até listar todos os arquivos.
cloud

Redis

Banco em memória muito usado para cache, fila leve, sessão e estrutura rápida.

Redis é excelente em velocidade, mas não deve ser tratado como banco relacional genérico.

Exemplo: Ex.: salvar sessão de login no Redis para leitura rápida entre várias instâncias.
geral

Refatoração

Mudança interna no código para melhorar clareza ou estrutura sem alterar comportamento esperado.

Refatorar reduz dívida técnica quando feito com teste e intenção clara.

Exemplo: Ex.: extrair função repetida em três arquivos para um módulo comum.
cloud

Réplica

Cópia sincronizada de instância ou banco usada para redundância ou leitura distribuída.

Réplica ajuda disponibilidade e escala, mas introduz desafio de atraso entre primária e secundária.

Exemplo: Ex.: relatório pesado consulta réplica de leitura para não travar banco principal.
back-end

REST

Estilo comum de API baseado em recursos, verbos HTTP e representação simples.

REST funciona bem para muitos casos, desde que contrato, idempotência e erros sejam pensados de verdade.

Exemplo: Ex.: GET lista pedidos, POST cria pedido, PATCH atualiza status.
infra

Rollback

Retorno para uma versão anterior depois de falha ou risco detectado.

Rollback rápido reduz impacto de release ruim, desde que artefato e banco tenham estratégia compatível.

Exemplo: Ex.: deploy novo aumenta erro e o time volta para a versão estável em minutos.
infra

Runtime

Ambiente que executa uma linguagem ou aplicação em tempo de execução.

Runtime inclui processo, memória, bibliotecas e comportamento da aplicação enquanto ela roda.

Exemplo: Ex.: Node.js é o runtime que executa JavaScript fora do navegador.
geral

SDK

Kit com bibliotecas, exemplos e documentação para integrar uma plataforma.

SDK reduz trabalho repetitivo e oferece contrato oficial para quem vai consumir um serviço.

Exemplo: Ex.: provedor de pagamento entrega SDK para criar cobrança sem montar requisição manual toda vez.
cloud

Serverless

Modelo em que você publica função ou serviço sem gerenciar servidor explicitamente.

Serverless reduz operação inicial, mas ainda exige cuidado com custo, latência e observabilidade.

Exemplo: Ex.: função processa upload quando arquivo chega no bucket sem servidor sempre ligado.
infra

Servidor

É um computador (físico ou virtual) que fica escutando pedidos de rede e responde com processamento ou arquivos. Na nuvem, "servidor" muitas vezes é uma VM, container ou função gerenciada, mas o conceito permanece.

Servidores rodam sistemas operacionais enxutos, serviços web (como nginx), runtimes de linguagem e agentes de monitoramento. Eles precisam de endereço IP, DNS, certificados TLS e políticas de firewall. Em escala, você pensa em balanceamento de carga, saúde das instâncias e custo por hora. Por isso infra não é só "subir uma máquina", é operação contínua.

Exemplo: Quando mil pessoas abrem o mesmo site ao mesmo tempo, várias instâncias de servidor atrás de um load balancer dividem o tráfego. Se uma instância morre, o balanceador para de enviar requisições para ela e sobe outra.
produto

SLA

Acordo formal sobre nível de serviço prometido, normalmente visto por cliente ou contrato.

SLA define expectativa de disponibilidade, tempo de resposta e penalidade em contexto comercial.

Exemplo: Ex.: contrato promete 99,9 por cento de disponibilidade mensal para clientes pagos.
infra

SLO

Meta interna de qualidade de serviço usada para orientar engenharia e operação.

SLO traduz confiabilidade em número acionável antes de virar quebra contratual de SLA.

Exemplo: Ex.: API deve responder em menos de 300 ms para 95 por cento das requisições.
cloud

Snapshot

Captura do estado de um volume, disco ou sistema em certo momento.

Snapshot ajuda recuperação, clonagem e auditoria, mas não substitui plano de restauração testado.

Exemplo: Ex.: criar snapshot do banco antes de migração arriscada.
back-end

SQL

É a linguagem declarativa para consultar e transformar dados em bancos relacionais. Você descreve o que quer; o otimizador do banco pensa em como buscar.

SQL cobre SELECT com JOINs, agregações, subconsultas, transações (BEGIN/COMMIT) e DDL (CREATE TABLE). Boas consultas usam índices adequados; más consultas travam produção com full table scan. ORMs ajudam, mas em performance crítica o SQL manual volta.

Exemplo: Relatório de vendas por região no último trimestre: você junta pedidos, clientes e filiais em uma query, filtra por data e agrupa. Errar JOIN duplica linhas e infla números. Por isso analistas revisam plano de execução.
seguranca

SSH

Protocolo seguro para acesso remoto e execução de comandos em outra máquina.

SSH é base de operação e automação, mas precisa controle de chave, permissão e auditoria.

Exemplo: Ex.: administrador acessa servidor Linux por SSH para investigar incidente.
seguranca

SSL/TLS

Camada criptográfica que protege comunicação em trânsito na web e em outros protocolos.

Hoje TLS é o termo correto, embora muita gente ainda diga SSL por costume.

Exemplo: Ex.: navegador mostra cadeado quando o site usa HTTPS com certificado válido.
geral

Stack

Conjunto de tecnologias usadas em uma aplicação ou produto.

Falar em stack é resumir linguagem, framework, banco, cloud e ferramentas principais do time.

Exemplo: Ex.: stack de um app pode ser React, Node, PostgreSQL e AWS.
front-end

State (estado)

Informação mutável que a interface usa para decidir o que mostrar e como reagir.

Estado mal controlado cria tela inconsistente e bug difícil de reproduzir.

Exemplo: Ex.: botão muda para loading enquanto a compra está sendo enviada.
cloud

Subdomínio

Parte de um domínio usada para separar aplicações ou áreas do mesmo site.

Subdomínio ajuda organizar tráfego, certificado e responsabilidade entre serviços distintos.

Exemplo: Ex.: api.exemplo.com e app.exemplo.com apontam para componentes diferentes.
qa

TDD

Prática de escrever teste antes do código de produção em ciclos curtos.

TDD força clareza de comportamento e design testável, mas não substitui pensamento sobre risco real.

Exemplo: Ex.: criar teste de cálculo de frete antes de implementar a função.
infra

Throughput

Quantidade de trabalho concluído por unidade de tempo.

Throughput ajuda medir capacidade do sistema, especialmente em fila, rede e processamento em lote.

Exemplo: Ex.: worker processa 5 mil mensagens por minuto em horário de pico.
seguranca

Token

Credencial curta usada para representar acesso, sessão ou autorização temporária.

Token precisa expirar, ser validado e nunca ficar exposto onde não deveria.

Exemplo: Ex.: app mobile envia token Bearer para chamar API autenticada.
infra

Uptime

Tempo em que um sistema permanece disponível e operacional.

Uptime alto importa, mas sem contexto de erro e latência ele pode enganar sobre qualidade real.

Exemplo: Ex.: site ficou disponível 99,95 por cento do mês, mesmo com picos de lentidão.
fundamentos

UUID

Identificador único longo gerado para reduzir colisão entre registros.

UUID é útil quando você não quer expor sequência previsível ou depende de geração distribuída.

Exemplo: Ex.: pedido recebe UUID para ser referenciado por vários serviços sem conflito.
produto

UX (User Experience)

É o efeito combinado de usabilidade, performance percebida, copy e confiança ao longo da jornada. UX não é só wireframe bonito: é reduzir erro humano e ansiedade em tarefas reais.

Pesquisa com usuários, testes de usabilidade e métricas (taxa de conclusão, tempo na tarefa) informam decisões. UX trabalha com acessibilidade, design de informação e feedback de sistema (loading, erros recuperáveis). Em squads, UX negocia trade-offs com engenharia: nem todo polimento vale o custo de implementação agora.

Exemplo: Formulário de cadastro longo gera abandono; UX propõe dividir em passos, salvar rascunho e mostrar progresso. Engenharia implementa validação inline e mensagens claras, com resultado medido em conversão.
cloud

VPC

Rede virtual isolada dentro de um provedor de cloud.

VPC organiza sub-redes, rotas, gateways e políticas de acesso entre recursos internos.

Exemplo: Ex.: banco fica em sub-rede privada da VPC e não recebe acesso direto da internet.
back-end

Webhook

Chamada automática enviada por um sistema para avisar outro sobre um evento.

Webhook é push de evento: você registra URL e o sistema notifica quando algo acontece.

Exemplo: Ex.: plataforma de pagamento chama seu webhook quando o boleto foi quitado.
back-end

WebSocket

Canal de comunicação persistente e bidirecional entre cliente e servidor.

WebSocket é útil quando a aplicação precisa de atualização quase em tempo real.

Exemplo: Ex.: chat mantém conexão aberta para entregar mensagem sem polling constante.
back-end

XML

Formato textual estruturado ainda usado em integrações legadas e documentos formais.

XML é mais verboso que JSON, mas segue forte em contextos governamentais e corporativos antigos.

Exemplo: Ex.: nota fiscal eletrônica trafega em XML com esquema validado.
cloud

YAML

Formato de configuração legível por humanos, muito usado em DevOps e Kubernetes.

YAML é simples de ler, mas sensível a indentação e fácil de quebrar com espaço errado.

Exemplo: Ex.: manifesto Kubernetes define imagem, réplicas e variáveis em YAML.
seguranca

Zero Trust

Modelo de segurança que parte do princípio de não confiar automaticamente em nada.

Zero Trust exige verificar identidade, contexto e permissão continuamente, mesmo dentro da rede.

Exemplo: Ex.: colaborador autenticado ainda precisa MFA e política específica para acessar dado sensível.
